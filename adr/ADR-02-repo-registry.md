# ADR-02-реестр-репозиториев

- **Статус:** принято
- **Дата:** 2026-09-15

## Контекст

ADR-01 требует анализировать любой публичный репозиторий без перезапуска.
Сейчас `create_router` принимает только один `repo_path`, и сервис видит
ровно один репозиторий на процесс. Хосту нужен способ подключать репозитории
по URL во время работы и выбирать, какой анализировать.

## Решение

1. **Каталог клонов.** `create_router` и `create_app` принимают необязательный
   `workspace_path`. Нужен хотя бы один из `repo_path` и `workspace_path`.
   Режим с одним `repo_path` остаётся как есть: публичный API не ломается.
2. **Реестр живёт в модуле `git`.** Класс `RepoRegistry` клонирует по URL,
   отдаёт `GitRepository` по идентификатору и перечисляет подключённые
   репозитории. От FastAPI он не зависит.
3. **Идентификатор репозитория** — имя каталога клона: читаемое имя
   репозитория плюс первые 16 символов SHA-256 от URL. Один URL всегда
   даёт один каталог, повторное подключение не клонирует заново.
4. **Без базы данных.** Исходный URL записывается в файл внутри каталога
   клона. После перезапуска реестр восстанавливается из содержимого каталога.
5. **API.**
   - `POST /repos` с телом `{url}` клонирует и возвращает описание репозитория.
   - `GET /repos` перечисляет подключённые.
   - Существующие эндпоинты принимают необязательный query-параметр `repo`.
     В режиме каталога без `repo` запрос отклоняется, в режиме `repo_path`
     параметр не нужен.

## Последствия

**Даёт:**
Новый репозиторий подключается из UI без перезапуска;
Подключённые репозитории переживают перезапуск процесса, если диск сохраняется;
Существующие хосты с `repo_path` продолжают работать без изменений.

**Платим:**
Клонирование идёт в запросе `POST /repos` и держит его до конца клона;
Удаления репозиториев нет, каталог только растёт;
На площадке без постоянного диска подключения теряются при перезапуске;
Разные написания одного URL (с `.git` или `/` в конце) дают разные каталоги
и отдельные клоны;
Клон не обновляется: коммиты, сделанные после подключения, не видны.

## Критерии приёмки

1. `POST /repos` с публичным https-URL возвращает идентификатор, репозиторий
   появляется в `GET /repos`.
2. Повторный `POST /repos` с тем же URL возвращает тот же идентификатор и не
   запускает git.
3. `GET /summary?repo=<id>` отдаёт данные этого репозитория; неизвестный `id`
   даёт 404.
4. Хост, созданный с одним `repo_path`, отвечает на все прежние эндпоинты
   без параметра `repo`.
5. После перезапуска процесса с тем же каталогом `GET /repos` показывает
   ранее подключённые репозитории.
