# ADR-04-деплой

- **Статус:** принято
- **Дата:** 2026-09-15

## Контекст

Definition of Done требует, чтобы сервис был доступен из интернета и показывал
большой публичный репозиторий. Своей площадки нет: по README её выдают по
запросу. Деплой нужно подготовить так, чтобы он подошёл к любой площадке,
которая запускает контейнеры.

Сервис вызывает git, поэтому git должен быть на сервере. Пакет должен
оставаться встраиваемой библиотекой, а не превращаться в отдельное приложение.

## Решение

1. **Docker-образ** на `python:3.11-slim` с установленным git.
2. **Хост ставит пакет из wheel**, как в `examples/host-vendor`. Образ собирает
   тот же артефакт, что выпускается `make package`, и не использует исходники
   напрямую.
3. **Хост-приложение** лежит в `deploy/app.py`: монтирует `create_router`
   в режиме каталога клонов (ADR-02) и `mount_static_ui` под `/git`,
   отдаёт `/health`.
4. **Настройка через переменные окружения:** `GITPULSE_WORKSPACE` — каталог
   клонов, `PORT` — порт uvicorn. `GITPULSE_REPO_PATH` необязательно добавляет
   один фиксированный репозиторий рядом с реестром.
5. **Каталог клонов** монтируется томом, если площадка это позволяет.
   Если нет, ограничение называется в README.
6. **Учётные данные площадки** в репозиторий не попадают. Разворачивает сервис
   владелец площадки.

## Последствия

**Даёт:**
Один образ запускается на любой площадке с контейнерами;
Деплой проверяет ту же упаковку, которую получают хосты;
Сервис развёрнут так же, как его встраивал бы любой хост.

**Платим:**
Без постоянного тома клоны пропадают при перезапуске, и репозиторий нужно
подключать заново;
Первое подключение большого репозитория занимает минуты;
Место на диске растёт с каждым подключённым репозиторием.

## Критерии приёмки

1. `docker build` собирает образ, в котором доступен `git`. — проверено.
2. Запущенный контейнер отвечает 200 на `/health` и отдаёт UI на `/git/`. —
   проверено, включая реальное клонирование публичного репозитория изнутри
   контейнера и то, что подключённый репозиторий переживает пересоздание
   контейнера при сохранённом томе.
3. Внутри контейнера пакет установлен из wheel, а не из исходников. —
   проверено.
4. Через UI на живом URL подключается большой публичный репозиторий, и его
   данные видны. — **не выполнено**: подключение к площадке ещё не завершено,
   публичного URL нет. Образ и хост-приложение готовы и проверены локально;
   этот пункт закроется вместе с публикацией живого URL.
5. README описывает запуск и ограничения деплоя. — проверено.
