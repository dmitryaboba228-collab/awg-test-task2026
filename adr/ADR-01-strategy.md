# ADR-01-стратегия

- **Статус:** принято
- **Дата:** 2026-09-15

## Контекст

Задание требует принимать любой публичный git URL, безопасно клонировать его
и анализировать. Шаблон умеет работать только с локальным путём, потому что
`create_router` падает с ошибкой, если `repo_path` не передан.

Ограничения заданы в `.cursor/rules/security.mdc`: проверять схемы, отклонять
`ext::` и подмену upload-pack, ограничивать размер и время, изолировать
клоны на диске.

## Решение

1. **Принимаются только URL со схемой `https://`.** Любая другая схема
   бракуется до вызова git. Это убирает `ext::`, который выполняет
   произвольную команду оболочки, `file://`, дающий доступ к локальной
   файловой системе и `ssh://`, требующий учётных данных, которых нет.
2. **Клонирование с флагом `--bare`.** Обычный клон кладёт ветки
   в `refs/remotes/origin/*`, а `GitRepository.list_branches` читает
   только `refs/heads/`. После обычного клона была бы видна одна ветка.
3. **Клоны изолированы на диске** в отдельном рабочем каталоге, по одному
   каталогу на репозиторий, вне дерева исходников.
4. **Каждое клонирование выполняется с явным таймаутом**, отдельным
   от таймаута обычных git-запросов.
5. **Учётные данные никогда не передаются.** Поддерживаются только
   публичные репозитории.

## Последствия

**Даёт:**
Любой публичный репозиторий анализируется без перезапуска;
Видны все ветки.

**Платим:**
Приватные репозитории не видим;
Место не освобождается и растет с каждым добавленным репозиторием;
Первый запрос к большому репозиторию будет медленным.

## Критерии приёмки

1. URL со схемой не`https` отклоняется с ошибкой, git не запускается.
2. URL, который начинается с `ext::`, отклоняется.
3. После клонирования публичного репозитория его ветки видны в UI.
4. Клонирование, которое превышает таймаут, завершается ошибкой, а не подвешиванием запроса.

## Дополнение: лимиты клонирования

- **Статус:** принято
- **Дата:** 2026-09-15

### Контекст

`.cursor/rules/security.mdc` требует ограничивать не только время, но и размер
клона. Решение выше размер не ограничивает. Кроме того, git по умолчанию
спрашивает логин, если репозиторий приватный или не существует, и запрос
висит до таймаута.

### Решение

1. **Git не спрашивает и не подставляет учётные данные.** Клонирование и любые
   докачки объектов запускаются с `GIT_TERMINAL_PROMPT=0` и
   `-c credential.helper=`. Пустое значение отключает помощники вроде связки
   ключей macOS: иначе git подставил бы токен владельца машины и склонировал
   приватный репозиторий. Приватный или несуществующий репозиторий сразу
   даёт ошибку.
2. **URL с логином или паролем отклоняется** до вызова git, например
   `https://user:pass@host/repo`.
3. **Для клона разрешён только протокол https:**
   `-c protocol.allow=never -c protocol.https.allow=always`. Так git не уйдёт
   на другой протокол при перенаправлении.
4. **Размер клона ограничен.** После клонирования проверяется размер каталога.
   Если он больше лимита, каталог удаляется, а запрос завершается ошибкой.
   Лимит задаётся параметром, по умолчанию 2 ГиБ — подтверждено: реализовано
   и проверено на живом клоне без замечаний.
5. **Один URL клонируется один раз.** Одновременные запросы на один и тот же
   URL ждут друг друга.

### Последствия

**Даёт:**
Приватный или несуществующий URL не держит запрос до таймаута;
Один репозиторий не заполнит диск целиком.

**Платим:**
Размер известен только после скачивания: слишком большой репозиторий успевает
скачаться, прежде чем его отклонят;
Лимит не защищает от заполнения диска множеством репозиториев среднего размера.

### Критерии приёмки

5. URL с логином или паролем отклоняется, git не запускается.
6. Клонирование приватного или несуществующего репозитория завершается ошибкой
   раньше таймаута.
7. Клон больше лимита удаляется с диска, запрос завершается ошибкой.
8. Два одновременных запроса на один URL приводят к одному клонированию.
