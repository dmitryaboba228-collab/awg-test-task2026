# ADR-03-метрики-и-фильтр

- **Статус:** принято
- **Дата:** 2026-09-15

## Контекст

Задание требует фильтр действий по пользователю и дашборд активности:
долю вклада по авторам и тренды, причём метрики должны быть объяснены.

Шаблон мешает этому в трёх местах:
- список авторов читает весь `git log`: вывод растёт с каждым коммитом,
  и на репозитории с сотнями тысяч коммитов превышает лимит в 8 МБ;
- тренд активности считается только по последним 500 коммитам, и это
  нигде не сказано;
- фильтра по автору нет.

Клон сделан без содержимого файлов (`--filter=blob:none`, ADR-01). Подсчёт
изменённых строк (`--numstat`) заставил бы git докачивать содержимое, и клон
перестал бы быть лёгким.

В bare-репозитории git читает `.mailmap` из `HEAD:.mailmap`. В клоне без
содержимого файлов этого объекта нет, и первое обращение к mailmap докачивает
его по сети прямо во время запроса.

## Решение

1. **Автор** — пара имя и email после применения `.mailmap`. Merge-коммиты
   не учитываются.
2. **Список авторов и доля вклада** берутся из
   `git shortlog -sne --no-merges <ревизия>`. Git отдаёт уже посчитанные итоги,
   поэтому вывод мал даже на большом репозитории. Ревизия (`HEAD` или ветка)
   передаётся всегда: в bare-репозитории `shortlog` без ревизии молча
   возвращает пустой результат.
3. **`.mailmap` докачивается один раз сразу после клонирования**, с теми же
   ограничениями, что и клон (ADR-01). Запросы к API после этого в сеть
   не ходят.
4. **Доля вклада = доля коммитов автора** среди всех коммитов без merge.
   Строки кода не считаются: так клон остаётся без содержимого файлов.
5. **Тренд активности** — число коммитов по ISO-неделям за всю историю.
   Считается по одним датам коммитов (`git log --format=%aI`), без лимита
   в 500 коммитов. Если вывод всё же превысит лимит, запрос завершается
   понятной ошибкой, а не обрезанными данными.
6. **Фильтр по пользователю** принимает email автора после mailmap.
   - Email проверяется по списку авторов, неизвестный даёт 404.
   - В git передаётся `--use-mailmap -F --author=<email>`, где email взят
     в угловые скобки. При `--use-mailmap` git сам сопоставляет старые адреса
     автора с основным. Скобки не дают `ada@example.com` совпасть
     с `bada@example.com`.
   - Фильтр применяется к ленте коммитов и к тренду. Доля вклада
     показывается по всем авторам, выбранный выделяется.
7. **UI объясняет метрики:** что такое доля, что считается автором, что merge
   исключены и что строки кода не учитываются.

## Последствия

**Даёт:**
Список авторов и доля работают на больших репозиториях;
Тренд честный: вся история, а не последние 500 коммитов;
Метрики совпадают с тем, что показывает `git shortlog`, их легко перепроверить;
Запросы к API не зависят от сети после клонирования.

**Платим:**
Доля по коммитам не отражает объём изменений: один большой коммит весит как
одна правка опечатки;
Автор с разными email без записи в `.mailmap` считается несколькими авторами;
Используется `.mailmap` на момент клонирования;
На очень длинной истории тренд может упереться в лимит вывода.

## Критерии приёмки

1. На репозитории с `.mailmap` два email одного человека дают одного автора,
   и в клоне без содержимого файлов тоже.
2. Сумма долей вклада равна 100 % с точностью до округления.
3. Фильтр по email автора оставляет в ленте и тренде только его коммиты,
   включая сделанные со старого email из `.mailmap`.
4. Фильтр по `ada@example.com` не захватывает коммиты `bada@example.com`.
5. Неизвестный email в фильтре даёт 404.
6. Тренд строится по всей истории, а не по последним 500 коммитам.
7. После клонирования запросы к авторам и доле не обращаются к сети.
8. В UI рядом с метриками есть объяснение, как они считаются, и их ограничения.
